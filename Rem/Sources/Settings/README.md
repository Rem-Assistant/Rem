# Settings (iOS)

> Everything behind the Settings tab on iOS. Shows your gateway connection status, subscription plan and usage, device permissions, paired devices (including Rem for Mac), skills you can enable, and your account/legal info.

Settings views for the iOS app covering gateway connection, billing, permissions, paired devices, skills management, and legal documents.

The nested Agent Settings Memory page is shared with macOS and currently presents only the read-only OpenClaw defaults Soul, Tools, and Agents. Generated diary/daily-log/wiki files and the legacy user-facts store are intentionally not shown; no stored data is deleted by this UI policy. Agent Settings also owns the shared Voice page: it loads the gateway's dynamic voice catalog, previews a voice through the gateway, and persists the canonical Talk selection across devices without exposing provider credentials.

## Key Files

| File | Purpose |
|------|---------|
| `SettingsView.swift` | Root settings screen — wraps `SharedSettingsView` with iOS-specific sections. The OpenClaw row lives under the “Your agent runtime” header and uses the shared OpenClaw vector mark. Other sections include permissions, skills, paired devices, about, legal (Terms/Privacy baked into `LegalContent` enum), and account deletion. `DevicePermissionsView` lists the App Store-approved iOS permissions (Calendar, Reminders, Microphone, Speech Recognition, Camera, Notifications) grouped into Device Data / Media & Voice / Notifications sections. Contacts and Location are intentionally omitted from the iOS release path. |
| `BillingSettingsView.swift` | Current plan and backend subscription-status display, authoritative daily/monthly request usage progress bars, and exact-plan actions: Free upgrades, Pro manages, unknown refreshes billing. Loading, stale-cache, and failure presentation come exclusively from `UsageService`'s generation-fenced request state; superseded view tasks cannot clear or publish over a newer refresh. Loading uses a truthful layout skeleton, and request failure hides any retained summary behind an unavailable/retry state so cached values are never labeled current. After StoreKit succeeds, the view awaits `IAPService`'s single entitlement + usage convergence operation and does not append another fetch that could re-pend a committed purchase. A device-local provider key never suppresses plan quota because it is not proof that the active gateway is using that credential. |
| `AppleSubscriptionSheet.swift` | `SubscriptionStoreView` wrapper (iOS 17+) for subscription group `21954380`; benefits and StoreKit product/legal metadata describe the current request-quota entitlement without promising deferred credits or paywalling device capabilities. Because StoreKit's native options provider cannot cancel after authority preparation fails, the sheet owns the subscribe control and enters StoreKit only through `IAPService`'s throwing, backend-token-bound admission path; it never substitutes a valid empty option set. Purchase completion joins `IAPService`'s canonical convergence operation; custom restore performs that convergence internally and is not followed by a duplicate callback chain. Restore marks the sheet pending immediately after `AppStore.sync` succeeds, before canonical convergence can fail. Retryable refresh failure stays visible and blocks accidental dismissal; a deterministic terminal ownership/validation rejection preserves the unresolved warning but exposes an explicit Close action so the user is not trapped. |
| `QuotaExceededSheet.swift` | Modal alert on quota exceeded — remaining quota display, legal links, and a structured daily/monthly title. Exact Free plans get Upgrade to Pro, exact Pro plans get Manage Subscription, and unavailable/unknown plan evidence gets a neutral Refresh Billing action. Cached denials expire at their UTC day/month reset boundary so the backend can re-evaluate instead of leaving chat locally locked. A successful purchase/restore clears the quota gate only after `IAPService`'s canonical fresh backend summary proves request capacity; the sheet does not issue a redundant post-commit refresh. |

## Patterns & Conventions

- **Shared settings core**: `SettingsView` delegates to `SharedSettingsView` (in `Shared/Views/`) with iOS-specific closures for permissions, billing, about, and sign-out handlers.
- **Connectors**: `SharedSettingsView`'s "Connectors" row (Composio-hosted connect for Gmail/Calendar/GitHub, replacing the old in-app OAuthClient) is on by default here — `SettingsView` no longer passes `showsConnectorsEntry: false`, so iOS gets parity with Mac's `MacFullSettingsView`.
- **Environment-based services**: Uses `@Environment` for `RemGatewaySessionManager`, `RemAuthService`, `UsageService`, `IAPService`.
- **Connection status mapping**: Status icons and colors are mapped from `GatewayConnectionState` (green=connected, orange=connecting, gray=disconnected, red=unauthorized/unreachable, yellow=pairingRequired).
- **Scene phase tracking**: `DevicePermissionsView` refreshes permission status when the app returns to foreground (after user grants in System Settings).
- **RPC for skills**: Skills loaded via `chatSession.request(method: "skills.status")` and toggled via `skills.update`.
- **Legal content**: Full Terms of Service (7 sections) and Privacy Policy (13 sections) are embedded in `LegalContent` enum within `SettingsView.swift`.
- **Account deletion**: Requires user to type "delete" for confirmation, calls backend `DELETE /api/v1/auth/me`.
- **Debug section (`#if DEBUG` only)**: When built in Debug, `SettingsView` passes a `debugSectionContent` closure into `SharedSettingsView` that surfaces internal-only entries. Currently exposes the SomeClaw relay client (#94) — see `RemClaw/Sources/SomeClaw/`.
